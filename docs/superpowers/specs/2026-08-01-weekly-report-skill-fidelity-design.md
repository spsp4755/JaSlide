# 주간 업무보고 스킬 재현도 개선 — 날짜 자동 계산 + 2단 컬럼/불렛 구조

**Goal:** "박태지_0723_업무보고_AI엔지니어링" 스킬로 생성할 때, 원본 템플릿의 실제 구조(추진실적/추진계획 2단 표, 이번 주/다음 주 날짜, 다단계 불렛)를 재현한다. 사용자가 날짜를 명시하지 않으면 추진실적은 이번 주(월~금), 추진계획은 다음 주(월~금)로 자동 계산한다.

**Context:** 등록된 템플릿의 원본 PPTX 슬라이드는 표 1개로 구성되어 있다 — 헤더 셀에 "추진실적 (2026.07.20 ~ 2026.07.24)" / "추진계획 (2026.07.27 ~ 2026.07.31)", 본문 셀은 `•`(대분류)/`-`(세부 항목, 다단계 들여쓰기)로 된 목록이다. 현재 생성 엔진은 이 구조를 전혀 모르고 "제목 + 평평한 불렛 목록"으로만 만들기 때문에 표/날짜/들여쓰기가 모두 사라진다.

이 문서가 다루는 범위는 이 문제 하나(날짜/표/불렛 재현)로 한정한다. "생성 엔진 전체 품질을 끌어올리는 것"은 범위가 정해지지 않은 별개의 훨씬 큰 주제이며, 여기서 다루지 않는다.

## 1. 날짜 컨텍스트 — 서버에서 계산해 프롬프트에 완성된 문자열로 주입

`apps/core-api/internal/generation`에 현재 시각 기준으로 "이번 주 월~금", "다음 주 월~금" 날짜 범위를 계산하는 함수를 추가한다. 이번 주는 오늘이 속한 주의 월요일부터 금요일까지, 다음 주는 그 다음 주의 월요일부터 금요일까지이며(주말 제외), `"2026.07.27 ~ 2026.07.31"` 형식 문자열로 만든다.

이 값을 `outlinePrompt`와 `slidePrompt` 양쪽에 **항상** 포함시킨다:
> "오늘은 {오늘 날짜(YYYY.MM.DD)}. 이번 주(월~금): {범위1}. 다음 주(월~금): {범위2}. 사용자가 명시적으로 다른 기간을 언급하지 않았다면 이 날짜를 사용하세요."

이 컨텍스트는 특정 스킬 전용이 아니라 모든 생성 요청에 항상 들어가는 일반 컨텍스트다. 날짜가 필요 없는 프롬프트는 그냥 무시되고, 날짜가 필요한 스킬(이 업무보고 포함)은 계산 없이 주어진 문자열을 그대로 사용하기만 하면 된다 — 이전 작업들에서 검증한 "LLM에게 계산을 시키지 말고 이미 계산된 결과를 주라" 패턴을 그대로 따른다.

## 2. `TWO_COLUMN` 콘텐츠 스키마 — 컬럼 헤더 + 불렛 레벨 반영

현재 `_add_two_column_slide`(`apps/renderer/src/generators/pptx_generator.py:996`)는 `content["bullets"]` 배열을 통째로 반으로 잘라 두 컬럼에 나누고, 각 불렛을 항상 `"• {text}"`로만 그려 불렛의 `level`(들여쓰기)을 완전히 무시한다. 컬럼 제목 개념도 없다.

새 콘텐츠 스키마(하위 호환 유지, `columns`가 없으면 기존 방식 그대로 폴백):
```json
{
  "heading": "주간업무 추진실적 및 계획",
  "columns": [
    {"header": "추진실적 (2026.07.20 ~ 2026.07.24)", "bullets": [
      {"text": "IT 운영 및 AI 연구", "level": 0},
      {"text": "프로젝트 관리 및 지원", "level": 1}
    ]},
    {"header": "추진계획 (2026.07.27 ~ 2026.07.31)", "bullets": [
      {"text": "IT 운영 및 AI 연구", "level": 0},
      {"text": "NL2SQL", "level": 1}
    ]}
  ]
}
```

**Go (`apps/core-api/internal/generation/llm.go`):**
- `slidePrompt`에 `TWO_COLUMN` 타입일 때의 스키마 설명 추가: `{"columns":[{"header":"...","bullets":[{"text":"...","level":0}]},{"header":"...","bullets":[...]}]}`, 정확히 2개 컬럼.
- `parseSlideContent`에 `validColumns(raw any) []map[string]any` 추가: 정확히 2개 컬럼, 각 컬럼은 비어있지 않은 `header`(string)와 1개 이상의 불렛 배열을 가져야 함. 각 불렛은 기존 불렛 파싱 로직(레벨 0-4, 텍스트 필수)을 재사용한다. 유효하지 않으면 `columns` 필드를 생략하고(에러 아님) 기존 `bullets`/`body` 경로가 폴백으로 동작하게 한다.

**Python (`apps/renderer/src/generators/pptx_generator.py`):**
- `_add_two_column_slide`를 수정: `content.get("columns")`가 유효한 2-컬럼 리스트면, 각 컬럼마다 (a) 헤더 텍스트 박스(굵게, 배경 강조는 하지 않음 — 템플릿 슬롯 계약은 건드리지 않음) + (b) 헤더 아래 불렛 목록을 그리되, 각 불렛의 `paragraph.level`을 그대로 설정한다(레벨 0은 `•`, 1 이상은 `-`, 기존 다단계 불렛 처리 관례를 그대로 따름 — 새 기호 체계를 만들지 않는다).
- `columns`가 없으면 기존 "bullets 배열을 반으로 자르기" 경로를 그대로 유지한다(하위 호환).

## 3. 이 스킬의 `outlineGuidance` 데이터 갱신 (코드 변경 없음)

"박태지_0723_업무보고_AI엔지니어링" 스킬(`id=go-c82b9a5413d51aa9444b818e1a1eca03`)의 `outlineGuidance`를 아래 내용으로 교체한다:
> "슬라이드 1개, TWO_COLUMN 타입만 사용. 왼쪽 컬럼 헤더는 '추진실적 (이번 주 날짜)', 오른쪽 컬럼 헤더는 '추진계획 (다음 주 날짜)'. 각 컬럼은 대분류 항목(level 0)과 세부 항목(level 1~2)으로 구성."

이 갱신은 이미 존재하는 "스킬별 자유 텍스트 가이드" 메커니즘(`apps/core-api/internal/generation/service.go`의 `skill.OutlineGuidance`)을 그대로 사용하는 데이터 변경일 뿐이며, 관리자 API(`PATCH` 또는 직접 DB 갱신)로 적용한다. 나중에 다른 2단 컬럼형 스킬을 등록해도 같은 방식(컬럼 헤더를 가이던스에 명시)으로 재사용 가능하다.

## 영향받지 않는 부분

- `html-template-contract.md`의 슬롯 계약은 변경 없음. 컬럼 헤더는 `_add_two_column_slide` 내부에서 동적으로 배치하는 텍스트 박스일 뿐, 새 슬롯 타입이 아니다.
- `TABLE`/`CHART` 스키마와 렌더링(직전 작업에서 완성)은 변경 없음.
- `columns`가 없는 기존 `TWO_COLUMN` 콘텐츠(과거 생성분)는 스키마상 완전히 하위 호환.

## 테스트 계획

**Go (`apps/core-api/internal/generation`):**
- 이번 주/다음 주 날짜 계산 함수: 특정 고정 날짜를 기준으로 월~금 범위가 정확한지(주 중간, 주말 등 여러 케이스), 문자열 포맷이 `"YYYY.MM.DD ~ YYYY.MM.DD"`인지.
- `outlinePrompt`/`slidePrompt`에 계산된 날짜 문자열이 포함되는지.
- `validColumns`: 유효한 2-컬럼 응답 통과, 컬럼 개수가 2가 아니거나 헤더가 비어있으면 무효 처리(→ `columns` 생략, 기존 경로 폴백).

**Python (`apps/renderer/tests/test_pptx_generator.py`):**
- `_add_two_column_slide`가 `content["columns"]`이 있을 때 각 컬럼 헤더 텍스트와 불렛 텍스트가 렌더링되는지, 불렛의 `level`이 `paragraph.level`에 반영되는지.
- `columns`가 없는 기존 `bullets` 방식이 여전히 동작하는지(회귀 없음).

**실사용 검증:**
- 스킬의 `outlineGuidance`를 갱신한 뒤, 로컬 스택에서 "0730 업무보고를 작성해줘"로 재생성 → 생성된 슬라이드가 표/평면 불렛이 아니라 2단 컬럼(헤더에 정확한 이번 주/다음 주 날짜) + 들여쓰기 불렛으로 나오는지 브라우저와 PPTX 내보내기 양쪽에서 확인.
